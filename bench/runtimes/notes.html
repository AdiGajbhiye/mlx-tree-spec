How this was measured

Requests

One server at a time on port 8000, driven by the same streaming OpenAI-compatible client. Temperature 0, up to 512 output tokens, thinking off where the server allows it. Every prompt starts with a random ID, so no engine can reuse a cached prefix.

Metrics

Prefill = prompt tokens ÷ time to first token (TTFT includes one decode step). Decode = (output tokens − 1) ÷ time from first to last streamed token. Token counts come from each server's own usage report.

Runs

One warmup request after each server start, then 3 measured runs per cell (2 at 32k), median reported. 60 s cool-down between configurations. Mac on AC power with caffeinate; other apps stayed open.

Prompts

Context sweep: real CPython stdlib source trimmed to exactly 128 to 32,768 tokens, then "summarize and write tests". Task mix: short prompts for code, prose, math, JSON and creative writing, plus a 2.7k-token file-edit prompt.

Lithos on this chip. lithos-metal 0.1.2 treats the 32-core M5 Max as an unmeasured fallback backend: no megakernel fusion and no tensor accelerator. Prefill runs at about 3 tok/s (roughly 33 s per 128-token chunk). Larger prefill chunks crashed the GPU (256 ran out of memory, 1024 page-faulted), and the DSpark draft ran out of memory with a 36k context, so both Lithos configs ran with --max-context 4096 and only the 128 and 1k context points. The project's published 200+ tok/s figures are for the 40-core M5 Max.

Things to know

Context copy. MTPLX turns on "context copy" by default, which drafts by copying spans from the prompt. C2 and E2 include it; C2n and E2n set MTPLX_CONTEXT_COPY=0 to show MTP alone. mlx-dspark ran with --no-lookup-drafts.

Swift 4-bit on MTPLX. MTPLX refuses the ukisai checkpoint because of its vision-encoder tensors, so C1/C2 use a text-only copy (the 501 visual.* tensors removed, all other weights byte-identical).

Different weights. Lithos and mlx-dspark run base Qwen3.8 27B; the others run the Swift 1.5 fine-tune. The quantizations differ too (NVFP4, affine 4-bit, MXFP4, IQ3_S). Compare speeds, not output quality.

Memory. Three MTPLX requests (E1 at 4k and on the edit task, E2n at 8k) were refused by its memory guard while other apps held memory; the other runs of those cells succeeded and the failed ones are left out. The same guard shrinks prefill when free memory is low, so MTPLX no-MTP prefill at 4k–8k varied between about 525 and 790 tok/s from run to run.
